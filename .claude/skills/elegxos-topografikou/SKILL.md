# Έλεγχος Τοπογραφικού / Διαγράμματος Κάλυψης / Κατόψεως (DWG/DXF)

Το skill εντοπίζει πιθανά **σφάλματα σε αριθμούς και κείμενα** σε σχέδιο CAD, με
**ανεξάρτητο επανυπολογισμό από το μηδέν** (η αριθμητική γίνεται σε script, όχι «στο μυαλό»)
και **καμία σιωπηλή διόρθωση** — μόνο επισήμανση.

Οικονομία tokens: δεν δίνεται ποτέ το αρχείο στο μοντέλο. Ένας parser εξάγει μόνο
κείμενα + αριθμούς + συντεταγμένες· οι αριθμητικοί έλεγχοι τρέχουν σε script· στο μοντέλο
φτάνει μόνο μια συμπαγής λίστα κειμένων προς γλωσσικό έλεγχο.

## Μηχανισμός ανά μορφή

| Μορφή | Engine | Σημείωση |
|---|---|---|
| **.dwg** | Node + `@mlightcad/libredwg-web` (LibreDWG σε WASM) | Διαβάζει έως AC1032· τρέχει offline |
| **.dxf** | Python + `ezdxf` | Το WASM build δεν διαβάζει DXF — χρησιμοποίησε ezdxf |

Και τα δύο βγάζουν **κοινό κανονικοποιημένο JSON**, οπότε ο ελεγκτής (`check.py`) είναι ένας.

## Ροή εκτέλεσης

Όλα τα scripts είναι στον υποφάκελο `scripts/`. Εργάσου σε προσωρινό φάκελο· αντίγραψε
εκεί το ανεβασμένο αρχείο πριν το τρέξεις (τα uploads είναι εκτός working dir).

### 0. Bootstrap (μία φορά ανά session)
```bash
cd <skill>/scripts
[ -d node_modules ] || npm install          # κατεβάζει libredwg-web (npm επιτρέπεται)
python3 -c "import ezdxf" 2>/dev/null || pip install ezdxf
```

### 1. Εξαγωγή -> κανονικοποιημένο JSON
```bash
# DWG:
node extract_dwg.mjs /tmp/work/input.dwg /tmp/work/norm.json
# DXF:
python3 -I extract_dxf.py /tmp/work/input.dxf /tmp/work/norm.json
```

### 2. Αριθμητικοί έλεγχοι (script)
```bash
python3 -I check.py /tmp/work/norm.json /tmp/work/findings.json
```
Το stdout δίνει σύνοψη· το `findings.json` περιέχει `numeric_findings` (έτοιμα ευρήματα)
και `texts_for_review` (συμπαγής λίστα κειμένων με γράμματα, χωρίς τον πίνακα συντεταγμένων).

### 3. Έλεγχοι κειμένου (μοντέλο)
Διάβασε **μόνο** το `texts_for_review` και εφάρμοσε τον κατάλογο ελέγχων κειμένου
(βλ. `references/checks.md`). Μη διαβάζεις ολόκληρο το `norm.json`.

### 4. Αναφορά
Συνένωσε αριθμητικά ευρήματα (από το script) + ευρήματα κειμένου (δικά σου) στη μορφή
αναφοράς του `references/checks.md`. Κατάληξε με σύνοψη έως 5 γραμμές. Πρόσφερε παραγωγή
`.docx` αν τη θέλει ο χρήστης (skill `docx`).

## Αριθμητικοί έλεγχοι (αυτόματοι — μηδέν tokens)

1. **Μήκη πλευρών**: κάθε ετικέτα «a-b=d» του πίνακα vs απόσταση από τις συντεταγμένες των κορυφών a,b.
2. **Εμβαδά**: κάθε αναγραφόμενο «E=…τ.μ.» vs εμβαδόν (shoelace) κλειστού polyline· αντιστοίχιση σε layer/handle.
3. **Κλείσιμο πολυγώνων**: κενό 1ης↔τελευταίας κορυφής.
4. **Συντεταγμένες ΕΓΣΑ87**: εύρος ευλογοφάνειας + απομακρυσμένες κορυφές (λάθος πληκτρολόγησης).
5. **Συγκρούσεις κορυφών**: ίδιος αριθμός κορυφής με δύο διαφορετικές συντεταγμένες.
6. **Μορφή ΚΑΕΚ**: 12 ψηφία (γεωτεμάχιο) ή 14 (οριζόντια/κάθετη ιδιοκτησία)· επισήμανση μόνο μη τυπικού πλήθους.
7. **Overrides διαστάσεων**: αριθμητικό κείμενο διάστασης vs πραγματικά μετρημένη γεωμετρία (κρίσιμο σε κατόψεις).
8. **Ενσωματωμένοι τύποι**: αποτίμηση εκφράσεων τύπου «8,00×4,00+1,20×1,75=34,10τ.μ.» και σύγκριση με το αναγραφόμενο.

Σε **κάτοψη** (χωρίς πίνακα συντεταγμένων) τα «Ε=…» είναι ετικέτες δωματίων χωρίς κλειστό
πολύγωνο: αναφέρονται ως πληροφορία («δεν επαληθεύτηκαν»), όχι ως σφάλμα.

Ανοχές: πλευρά 1,5 εκ., εμβαδόν 0,05 τ.μ., κλείσιμο 1 εκ. (στο `check.py`, παραμετροποιήσιμες).

## Δηλώσεις & όροι δόμησης (μόνο σε τοπογραφικό)

Το `check.py` ανιχνεύει αυτόματα (όταν το σχέδιο είναι τοπογραφικό) την **παρουσία**:
**Δήλωση Ορίων, Δήλωση Δασικών, Δήλωση Ν.651/77, Όροι Δόμησης, Δήλωση Αρτιότητας**.
Όποια δεν εντοπιστεί → εύρημα `ΕΛΕΓΧΟΣ/δήλωση` («δεν εντοπίστηκε — επιβεβαίωσε αν λείπει ή
είναι διατυπωμένη αλλιώς»). Στο `findings.json` υπάρχει `declarations` (παρουσία ανά ενότητα)
και `sections.artiotita` / `sections.oroi` (τα σχετικά κείμενα).

**Έλεγχος συνάφειας όρων δόμησης ↔ αρτιότητας (μοντέλο):** από το `sections` προσδιόρισε το
καθεστώς (εντός σχεδίου / εντός ορίων οικισμού / στάσιμος οικισμός / εκτός σχεδίου) και έλεγξε
αν **συνάδει** με τις τιμές αρτιότητας/προσώπου που αναγράφονται. Παράδειγμα ασυνέπειας:
καθεστώς «εκτός σχεδίου» αλλά αρτιότητα 500 τ.μ. (τιμή οικισμού), ή αντίστροφα.

- Επισήμανε κάθε αντίφαση ως εύρημα.
- Τα **αριθμητικά όρια** (π.χ. 4.000 / 2.000 / 1.200 / 500 τ.μ., πρόσωπο) **ΜΗΝ** τα
  επιβεβαιώνεις από μνήμη: επαλήθευσέ τα στο **ΦΕΚ/νόμο που αναφέρει το ίδιο το σχέδιο**
  (αναζήτηση σε πηγή αν είναι προσβάσιμη), αλλιώς σημείωσέ τα ρητά «προς επαλήθευση».
- Αν το σχέδιο επικαλείται ΦΕΚ όρων (π.χ. ΑΑΠ), ανάφερέ το ως σημείο επαλήθευσης, χωρίς να
  κρίνεις το περιεχόμενό του από μνήμη.

## Έλεγχοι κειμένου (μοντέλο) — βλ. `references/checks.md`

Ελέγχεις: ορθογραφικά σε τυποποιημένες νομικές/τεχνικές φράσεις (ιδίως ασυνέπεια μεταξύ
παρόμοιων παραγράφων), ασύμμετρα/μη ισορροπημένα εισαγωγικά και παρενθέσεις, ασυνέπεια
δεκαδικού διαχωριστή (κόμμα vs τελεία σε αριθμούς), κενά/placeholder πεδία
(ΚΛΙΜΑΚΑ, ΧΡΟΝΟΣ, αριθμός ΚΗΔ, κ.λπ.), ασυνέπειες ονομάτων/τοπωνυμίων/ΚΑΕΚ μεταξύ θέσεων.

### ΑΠΟΚΛΕΙΣΜΟΙ (ΜΗΝ τα αναφέρεις ποτέ)
1. **ΜΗΝ** αναφέρεις ασυνέπεια μονάδας «μ2» vs «τ.μ.».
2. **ΜΗΝ** αναφέρεις μικτούς ελληνικούς/λατινικούς χαρακτήρες σε λέξεις.
3. **ΜΗΝ** κάνεις έλεγχο «αποδεκτής απόκλισης εμβαδού κτηματολογίου» (7%)· αγνόησέ τον τελείως.

## Κανόνες

- **Καμία σιωπηλή διόρθωση**: επισημαίνεις, δεν αλλάζεις τιμές.
- **Καμία επινόηση**: ΦΕΚ/νόμους/άρθρα τα αναφέρεις ως «προς επαλήθευση», δεν τα επιβεβαιώνεις από μνήμη.
- **Εμπιστευτικότητα**: ονόματα/ΑΦΜ/ΚΑΕΚ αναπαράγονται ακριβώς, ποτέ σε εξωτερική αναζήτηση.
- Αν `check.py` δώσει «layer πίνακα: None», το σχέδιο δεν έχει τυπικό πίνακα συντεταγμένων
  (π.χ. κάτοψη ή συγκεντρωτικό)· τρέξε τους υπόλοιπους ελέγχους και πες το ρητά.
